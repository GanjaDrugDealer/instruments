# Общие правила для всех проектов

Один файл для всех агентов: Claude, Codex, Antigravity. Где правило только для одного из них — так и сказано.

## Время — только Турция (Стамбул). ГЛАВНОЕ

Любое время в ответах, отчётах, планах, расписаниях и записях (`STATE.md`, `DECISIONS.md`, коммиты) — **по Стамбулу
(UTC+3)**, с пометкой «Стамбул». «Сегодня», «завтра», «в 19:00» — тоже по Стамбул. Серверы, журналы и программы живут
в своём поясе (Netcup — CET/CEST, UTC) — время оттуда **пересчитать в Стамбул**, прежде чем назвать человеку; сырое
время сервера без пересчёта не писать. Расписания (таймеры, cron, рутины) задавать с явным `Europe/Istanbul`.

## Ссылки на файлы — ГЛАВНОЕ

В ответах пользователю ссылки на файлы давать **только с полным абсолютным путём**,
пробелы кодировать как `%20`:

- Mac: `[STATE.md](/Users/artemganza/Desktop/AI%20Projects/Claude/youtube-shorts-cs/STATE.md)`
- Windows: `[STATE.md](file:///C:/AI%20Projects/Claude/youtube-shorts-cs/STATE.md)` — схема `file:///`, диск `C:/`, прямые слэши, пробелы `%20`, кириллицу оставлять как есть (не кодировать)

Относительные ссылки (`STATE.md`, `docs/…`) приложение ищет от папки, где запущена
сессия, а не от папки проекта → «couldn't find this file». Так было 2026-09-25.

Дубли: скилл `file-links` (`_instruments/skills/shared/file-links/SKILL.md`, для всех агентов).

## Проверка перед сдачей — смотреть результат своими глазами. ГЛАВНОЕ

Никогда не сдавать задачу пользователю («готово», «проверь», «задача закрыта») без **собственной проверки реальной работоспособности**:
1. Скрипты, API, бэкенд — запустить сквозной тест и проверить фактический вывод и код возврата 0.
2. Интерфейсы (Web UI, страницы, дашборды, Студия) — **обязательно сделать скриншот результирующего интерфейса** (через Playwright / headless Chrome / скрипт) и **лично посмотреть скриншот**, убедившись, что элементы, медиафайлы (фото, видео), карточки и кнопки реально отрисовались, а не показывают заглушки «Файл не найден» / «НЕТ НА ДИСКЕ» / 404.
3. Только после успешного подтверждения глазами — сдавать задачу с прикреплённым скриншотом / фактом проверки.
Так решено 2026-11-17: сдача без проверки ломала доверие из-за неработающих ссылок на медиа.

## Конец задачи — коммит, пуш, совет про clear

Когда задача завершена, **сам, не спрашивая**:

1. Обновить справочники и точку продолжения по разделу «Что куда записывать».
2. Если проект в git — закоммитить и запушить в его `origin` (GitHub-аккаунт GanjaDrugDealer). Перед коммитом
   посмотреть дифф: секреты, `.env`, личные данные в репозиторий не едут. Пуш — только в ветку проекта, без force.
3. В самом конце ответа одна короткая строка: «Задача закрыта — можно clear/архив.» (в dsh — «можно начинать новую
   сессию»: команды clear там нет, контекст чистит новая сессия, а старую часть сжимает `/compact`). Если что-то
   ещё висит (ждёт проверки пользователя, идёт фоновая работа или другая сессия, пуш не прошёл) — вместо этого
   коротко, что именно мешает.

Чтобы экономить токены, предлагай новый чат и между независимыми задачами, когда текущая работа
завершена и следующей уже не нужна история переписки. Перед этим сохрани решения и точку продолжения.

Согласованный и подтверждённый план (пользователь выбрал вариант или сказал «да») — после проверок доводить до конца:
выкладка, коммит, слияние рабочей ветки в `main`, пуш — без повторного «выложить?». Спрашивать, только если план
не согласован или проверки упали. Установки с правами админа, входы в аккаунты, пароли — только пользователь.
Коммиты — без следов ИИ (скилл `git-release-discipline`).

## Что куда записывать — память, проект, правила

- **Нужно в любой сессии** — в `CLAUDE.md` проекта. Здесь цель, порядок старта, общие для проекта решения и карта «задача → что читать».
- **Пригодится при следующем обращении к теме** — сразу обнови действующий справочник. Если его ещё нет, сам создай
  `docs/context/<тема>.md` с первым устойчивым фактом и добавь путь в карту. В старом проекте перенеси сведения по этой теме при работе с ней, сохранив в прежнем месте ссылку.
- **Нужно для продолжения работы** — в `STATE.md`. По каждой активной задаче оставь текущую стадию, следующий шаг
  и незавершённую проверку или зависимость. При передаче смены замени устаревшее, сними закрытое, сохрани другие активные задачи.
- **Правило работы с пользователем, верное для любого проекта** — сюда, в `_instruments/rules/CLAUDE.global.md`.
- **Память агента** (`~/.claude/projects/…/memory`) — только личное, что не должно ехать в git (доступы к чужим серверам
  и т. п.). Она живёт на одной машине и другим агентам не видна. Так решено 2026-11-03.

Решения, поправки пользователя и устойчивые факты записывай сам, с датой, в одном месте. Обнови прежнюю запись, если она есть.
В ответе кратко укажи, где записал. Если важно сохранить причину решения, используй действующий журнал решений или разбор.
Разовые подробности и то, что уже видно из Git, можно опустить. Исполнитель по ТЗ передаёт факт в отчёте, ведущий обновляет справочник и карту.
Проектная память всех агентов хранится в файлах проекта. Встроенная память Antigravity (Knowledge) и MCP-память не используются.

## Работа с пользователем

- Общаться только по-русски, включая вопросы и сводки; термины и команды — как есть.
- Русский текст в английской раскладке («gjghj,eq» = «попробуй») — расшифровать по ЙЦУКЕН, коротко показать
  расшифровку и действовать; переспрашивать только при двусмысленности.
- Инструкции по чужому интерфейсу (iPhone — он на английском, кабинеты сайтов) — по одному короткому шагу за
  сообщение, ждать скриншот. Полную инструкцию — файлом в `out\`, в чат не вываливать.
- Непонятная ошибка внешнего сервиса или сторонний способ (чужой client_id, обходной вход, библиотека) — сначала 1–2
  поиска «<способ> не работает <месяц год>», вывод с источником, потом план одной попыткой. Не гонять человека
  по догадкам: повторившаяся ошибка сервиса — причина не в нём. Так было 15–20.10 со входами в Telegram и VK.
- Не записывать в файлы проектов и в память, что пользователь сам под VPN или где он находится. VPN в коде —
  только как поведение продукта для всех.
- Файл с доступами (`*.env`, `*token*`, `*key*`) сначала смотреть по форме (`head -c 20`, `grep -c BEGIN`), значения
  не печатать: `.env` может оказаться голым приватным ключом, маска `sed 's/=.*/…/'` его не скроет (05.10).
- Новая или пустая папка проекта — сначала структура по скиллу `project-structure` (`new-project`), потом работа.
- В папке могут одновременно работать несколько сессий: перед коммитом `git status`, в коммит только свои файлы
  (`git add <файлы>`, не `-A`); чужие незакоммиченные не трогать, ветку при грязном дереве не переключать.

## Объёмная работа — сначала исполнитель, а не урезать задачу

Если задача больше, чем разумно сделать самому (сотни картинок или скринов, массовая расшифровка, разбор длинных
выгрузок, однотипный код), **до того как сократить объём или написать «не разбирал»** — просмотреть скиллы-исполнители
и выбрать дешёвый путь: `antigravity` (agy: Gemini по подписке, сам открывает картинки, текст по схеме),
`local-models` (Ollama на ПК, приватные данные), `jules` (код по ТЗ). Выбор и цену назвать одной строкой;
решения и приёмку результата оставлять себе. Так было 2026-10-28: ~400 скринов чуть не остались непрочитанными,
хотя agy стоял на ПК. Владелец 23.10: «agy — работяга, ты — начальник»: код по ТЗ и черновую аналитику по
возможности отдавать agy, себе — постановку, выбор и приёмку. Задача на картинки — приоритет в любом проекте:
прерывает текущую, после картинок вернуться к прерванному.

## Сбой — чинить причину, а не объяснять симптом. ГЛАВНОЕ

До исправления определить, по какому наблюдаемому результату на исходном сценарии будет видно, что сбой устранён.
При сдаче назвать, где получен каждый результат: в локальном тесте или в рабочем запуске. Если рабочий запуск ещё
не проверен, сказать об этом прямо.

Если ошибся сам, исправь результат и проверь его в исходном сценарии. Если ошибка может повториться,
сам выбери и внедри в пределах задачи конкретную меру против повтора (например, тест или уточнение
действующего правила). Коротко сообщи, что изменил. Если мера требует расширить задачу, предложи её пользователю.

Тревога, ошибка, «остановилось»: **дойти до источника и исправить его**, а не пересказать журнал и ждать слова.
Порядок: сначала прочитать справочник линии в проекте (как это устроено сейчас; пометки в журналах бывают
устаревшими), найти, где именно рвётся цепочка, починить там, где рвётся, тест на этот случай, выкладка, потом
закрыть сам сбой (пересобрать сорвавшийся результат). Остановку «нужен человек» тоже чинить: если человек
нужен из-за того, что код чего-то не умеет, — научить код. Так было 2026-11-06: тревога «План дня» объяснена
как «нет текста по ссылке, ждём редактора», а на деле сборщик MAX не вынимал текст из присланного `.docx`;
вдобавок справочник с «основной автор — Gemini, Claude не используется» не был прочитан.

## Не караулить — долгое и GUI только в фоне со сроком. ГЛАВНОЕ

Команда, которая может зависнуть (управление окнами через UIA/pywinauto/AHK, чужая программа, сеть, всё дольше
1–2 минут), **запускается только в фоне** (`run_in_background`) с жёстким сроком, который реально убивает дерево
процессов (`taskkill /T /F` по PID на Windows — `timeout` из Git Bash зависший `python` не убивает). Свой срок
каждой операции знать заранее; вышел срок ×2 — **сразу смотреть причину** (скриншот, окна процесса, журнал), а не
ждать дальше. Пока фон идёт — делать другую работу или отчитаться человеку, а не сидеть в одном вызове. В конце
каждого шага — коротко сказать человеку, что идёт и сколько ещё. Так было 2026-11-18: скрипт переключения
настройки Capture One запущен на переднем плане, повис на модальном окне C1, вызов не вернулся ~4 часа — ночь
опытов потеряна, человек ждал.

## Не изобретать костыли — сначала найти инструмент или спросить. ГЛАВНОЕ

Прежде чем работать с чужой средой вручную (Google Docs, Notion, Figma, любое веб-приложение через браузер
или клики), **поискать готовый путь**: коннектор/MCP, плагин, скилл, официальный API, экспорт-импорт файла
(скачать → править локально → залить). Нашёл несколько путей или ни одного — **коротко спросить пользователя**,
назвав варианты и цену. Лишний вопрос дешевле, чем костыль. Если выбранный путь начал сыпаться (второй-третий
обходной манёвр подряд) — остановиться и спросить, а не бороться дальше. Так было 2026-11-02: правки статьи
вносились в Google Doc скриптами и кликами через браузер, ушла куча лимитов и побочные поломки, хотя проще было
скачать документ и залить правленую копию (или подключить коннектор).

## Инструменты

Использовать официальные сборки, сверять контрольную сумму и хранить инструменты в `bin/` проекта

## Где живут общие правила и скиллы

Этот файл собран установщиком из `_instruments` (закрытый репозиторий `instruments`; работа над скиллами —
в мастерской `Claude/ai-workshop`, репозиторий `ai-workshop`) и разложен всем агентам: Claude — `~/.claude/CLAUDE.md`,

(`_instruments/rules/CLAUDE.global.md`) + личные правила человека из репозитория (`rules/personal/<профиль>.md`,

в git не едут). Правила проекта — в `CLAUDE.md` проекта, сюда не тащить.

Правило для всех людей — в `rules/CLAUDE.global.md`; про конкретного человека, его машины и аккаунты — в его
`rules/personal/<профиль>.md`. Здесь, в собранном файле, не править. После правки в `_instruments` — коммит и пуш.
Другие машины подтянут сами: автосинхронизация при входе в систему, ночью в 04:00 (Стамбул) и при старте сессии Claude
(README, «Автосинхронизация»). Если хук пишет, что `_instruments` не синхронизирован, — одной строкой сказать
пользователю причину; незакоммиченное в `_instruments` не оставлять.

## dsh

`dsh web` берёт эту же сборку из `~/.agents/AGENTS.md` (рядом читает `$DSH_HOME/AGENTS.md`, если он есть) и те же
скиллы из `~/.agents/skills/`. Правила проекта — `AGENTS.md` и `CLAUDE.md` в корне: грузятся по цепочке от корня
репозитория до рабочей папки, одинаковые по содержимому файлы не дублируются (потолок на всю цепочку — 64 КБ).
Скиллы проекта dsh ищет в `<проект>/.dsh/skills` и `<проект>/.agents/skills`, а `.claude/skills` не читает — в
проекте нужен переходник `.dsh/skills` → `.claude/skills`. Контекст чистится новой сессией (боковая панель, New
Session), а не командой clear; `/compact` сжимает старую часть, не начиная заново.
