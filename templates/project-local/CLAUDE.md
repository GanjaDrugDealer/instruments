# <project-name>

## Начало смены

1. Через `read_file` прочитать `STATE.md` — там текущая стадия и следующий шаг.
2. Если в `STATE.md` стоит «контекст не собран» — выполнить раздел
   «Сбор контекста» ниже, больше ничего не делать.

## Сбор контекста (первый чат нового проекта)

1. Расспросить владельца: цель проекта, вход и выход, на чём писать,
   какие ограничения.
2. Через `update_section` заполнить раздел «О проекте» этого файла.
3. Обновить `STATE.md`: снять «контекст не собран», записать следующий шаг.

## Рабочие правила

1. Работать только внутри папки проекта. За пределы не выходить.
2. Не выдумывать факты — если не знаешь, скажи прямо.
3. Всё важное — в файлы. Чат пропадёт, файлы останутся.
4. Существующие файлы менять через `update_section` (один раздел, остальное не трогается);
   `write_file` — только для новых файлов.
5. Соблюдать `GUARDRAILS.md`.

## Передача смены

`/итог` (или «подведи итог»): составить итог по его шаблону, сохранить через `save_summary`
(имя `docs/ГГГГ-ММ-ДД_itog-<тема>.md` он составит сам), обновить в `STATE.md` разделы
«Сейчас» и «Следующий шаг» через `update_section`.

`/контекст` (или «обнови контекст»): новые факты из разговора — через `update_section`:
где мы и что дальше — в `STATE.md`; главные устойчивые факты — коротко в «О проекте» этого файла;
подробности по теме — в `docs/context/<тема>.md`. Ничего не удалять. Пресет обновится сам.

Следующий чат начнёт с чтения `STATE.md` и продолжит с того места.
Имена файлов видны за пределами проекта (списки, логи) — в именах только нейтральные слова,
без деликатных подробностей. Подробности — внутри файла.
