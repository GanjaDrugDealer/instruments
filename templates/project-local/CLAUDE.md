# <project-name>

## Начало смены

Через `read_file` прочитать `STATE.md` и открыть по карте ниже справочник текущей задачи.

## Рабочие правила

1. Работать только внутри папки проекта. За пределы не выходить.
2. Не выдумывать факты — если не знаешь, скажи прямо.
3. Всё важное — в файлы. Чат пропадёт, файлы останутся.
4. Существующие файлы менять через `update_section` (один раздел, остальное не трогается);
   `write_file` — только для новых файлов.
5. Соблюдать `GUARDRAILS.md`.

## Передача смены

`/итог` (или «подведи итог»): составить итог по его шаблону, сохранить через `save_summary`
(имя `docs/ГГГГ-ММ-ДД_itog-<тема>.md` он составит сам). Через `update_section` обновить в `STATE.md`
стадию, следующий шаг и открытые вопросы по активным задачам. Убрать и из «Сейчас» закрытые проверки, от которых следующий шаг уже не зависит.

При первом устойчивом факте по теме, к которой вернёмся, сразу обновить существующий справочник
через `update_section` или создать `docs/context/<тема>.md` через `write_file`. В «Где что лежит»
добавить обычный путь без `@`. При команде `/контекст` («обнови контекст») применять тот же порядок.
В «О проекте» оставлять только сведения, нужные в любой сессии. Пресет обновится сам.

Следующий чат начнёт с чтения `STATE.md` и продолжит с того места.
Имена файлов видны за пределами проекта (списки, логи) — в именах только нейтральные слова,
без деликатных подробностей. Подробности — внутри файла.
