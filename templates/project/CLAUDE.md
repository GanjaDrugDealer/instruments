## Сбор контекста (первая сессия нового проекта)

Каждый проект свой: контекст, скиллы и агенты выясняются здесь, не заранее.

1. Расспросить пользователя: цель, вход и выход, ограничения, на чём писать,
   кто ведёт проект (Claude, Codex, Antigravity или несколько агентов по очереди).
2. Заполнить разделы «О проекте», «Стек», «Инструменты проекта» этого файла.
3. Решить, какие нужны скиллы (`.claude/skills/<имя>/SKILL.md`) и агенты
   (`agents/`). Общий скилл, нужный постоянно, - копировать внутрь проекта.
4. Ненужные папки из шаблона удалить. Если второго агента нет - удалить
   раздел «Для агента-исполнителя» из `GUARDRAILS.md`.
5. Обновить `STATE.md`: снять «контекст не собран», записать следующий шаг.

Разросся - подробности по линиям в `docs/context/<линия>.md`, здесь карта «задача про… → читать»
(простым путём, не `@`). Правило - скилл `project-structure`, «Один вход в контекст».

## Как подключить эту папку к агенту

Папка самодостаточна: всё, что нужно для работы над проектом, лежит внутри.
Ничего за её пределами не требуется.

- **Claude Code / новый аккаунт Claude**: открыть папку как рабочую директорию.
  `CLAUDE.md` и `.claude/skills/` подхватятся сами.
- **Codex**: открыть папку как проект. Читать `AGENTS.md`, он ведёт сюда.
- **Antigravity**: открыть папку как workspace. Читать `AGENTS.md`, он ведёт сюда.
- **Локальный агент (Ollama и подобные)**: скормить `CLAUDE.md` как системный
  контекст, `.claude/skills/*/SKILL.md` - как дополнительные инструкции.

Внутри проекта не должно быть абсолютных путей за пределы папки и реальных
секретов. `.venv`, `.git`, `node_modules` внутри - нормально: хранилище
локальное, облачной синхронизации нет. Секреты - в `.env`, он закрыт
`.gitignore`; в репозиторий едет только `.env.example` с именами переменных.
