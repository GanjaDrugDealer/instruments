# Коммит и push

Найди настоящий git-корень по контексту проекта. Рабочая папка с STATE.md
может быть отдельно от репозитория исходников (мастерская ai-instruments:
исходники в ../../_Instruments). Прочитай инструкции проекта и проверь
git status -sb, текущую ветку и git remote -v.

В проектах пользователя завершённую задачу коммить и отправляй в origin
без повторного вопроса, согласно его глобальным правилам. Это относится
к GitHub; публикация сайта, релиз, деплой и отправка сообщений — отдельные действия.

Перед коммитом просмотри git diff и новые файлы: исключи секреты, .env,
личные данные и посторонние изменения. Не используй git add . вслепую:
добавляй файлы выполненной задачи. Проведи проверки, подходящие изменению,
обнови STATE.md или другой журнал проекта, проверь staged diff и diff --check.

Сделай коммит с описанием результата и push только текущей ветки проекта.
При настроенном upstream используй его; иначе укажи origin и точное имя ветки.
Не делай force push, reset --hard и не удаляй чужие изменения. При отклонении
из-за новых удалённых коммитов сначала fetch и анализ расхождений; не запускай
автоматический цикл повторов или переписывание истории.

Подтверди отправку сравнением HEAD с удалённой веткой (git ls-remote) и
git status -sb. В ответе укажи короткий хеш и результат push. Если push не прошёл,
сообщи причину и что осталось; не объявляй задачу закрытой.

На Windows существующие git/gh credentials могут быть недоступны в ограниченном
процессе. Проверь доступ через предусмотренный инструментом запрос расширенных
прав; не меняй safe.directory глобально и не сбрасывай авторизацию по первому
сбою. gh auth status вызывай без --show-token; секреты не печатай.
