# Слежение архитектора за исполнителями

Пара к `watch-tasks`: исполнитель ловит задачи, архитектор ловит сдачу. Пользователь
не должен пересказывать архитектору, что сделал исполнитель.

## Договорённость о сдаче (проверить, что она есть в проекте)

- Отчёт — **файлом** `docs/tasks/reports/<ГГГГ-ММ-ДД>_<ID задачи>_report.md`. Чат исполнителя
  архитектору не виден (2026-09-26: отчёт T2.2 остался в чате, приёмка шла вслепую).
- В каждом ТЗ — раздел «Куда сдавать» с этим путём. Папку отчётов можно писать в любой задаче.
- Если правила нет — сначала записать его на доску задач проекта и в `AGENTS.md`.

## Запуск (Claude Code)

`Monitor` (отложенный — `ToolSearch select:Monitor`), сразу после выдачи ТЗ:

```
Monitor(
  description = "сдача исполнителей в <проект>",
  timeout_ms  = 1800000,
  command     = 'zsh "<этот скилл>/scripts/watch-executors.sh" "<папка проекта>"'
)
```

События: `СДАЧА <файл>` — главный сигнал; `В РАБОТЕ <файлы>` — исполнитель правит (для сведения,
не принимать); `КОММИТ` — разобрать, свой или чужой. Истёк таймаут — перезапустить тем же вызовом.

## Приёмка при `СДАЧА`

1. Прочитать отчёт и ТЗ задачи.
2. `git status --short` + `git diff --stat`: изменены **только** файлы из «Можно трогать»
   (+ папка отчётов). Чужой файл тронут — не принято, как бы хорошо ни выглядело.
3. `git diff` по файлам задачи — прочитать, а не верить пересказу.
4. **Самому** прогнать команды из раздела «Приёмка» ТЗ (в свой scratchpad), не доверяя цифрам отчёта.
   Для видео — листы кадров, у стыков — 10–30 к/с; звук — `ebur128`, `astats`.
5. Решение:
   - **Принято** — коммит работы исполнителя отдельно и **по путям** (не `git add -A`),
     статус на доске «принято <дата>», строка в `STATE.md`.
   - **Не принято** — ТЗ `<ID>.<N+1>` с конкретными дефектами и критерием «готово, когда…»,
     статус на доске, коротко пользователю.
   - Дефект в данных архитектора (разметка, параметры) — исправить самому, отметить в отчёте пользователю.
6. Пользователю: что принято, что найдено, что дальше; ссылки — абсолютными путями.

## Не делать

- Не опрашивать вручную (`sleep` + проверки каждый ход) — только фоновый монитор.
- Не принимать по отчёту без своих прогонов.
- Не коммитить незаконченную работу исполнителя (`В РАБОТЕ`) в свои коммиты.
- Не править файлы исполнителя во время его работы — только через ТЗ.
