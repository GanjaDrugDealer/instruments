# Слежение архитектора за исполнителями

Пара к `watch-tasks`: исполнитель ловит задачи, архитектор ловит сдачу. Пользователь
не должен пересказывать архитектору, что сделал исполнитель.

## Главное: молчать, если не касается

Владелец 2026-09-28: «не пиши сюда, если задача не для тебя». Каждое событие монитора приходит в чат
как отдельный ход — отвечать на него текстом **нельзя**, если оно не про мою роль:
- чужие задачи, отчёты и коммиты других агентов, правки STATE не про меня — **ни слова**;
- продление монитора (истёк таймаут, «СЛЕЖУ: …») — перезапустить **молча**;
- мои собственные правки, вернувшиеся событием, — молча.

Пишу пользователю только когда: подхватил **свою** задачу / сдал её / нашёл то, что ломает мою работу
или требует его решения. Одна-две строки, по делу.

## Договорённость о сдаче (проверить, что она есть в проекте)

- Отчёт — **файлом** `docs/tasks/reports/<ГГГГ-ММ-ДД>_<ID задачи>_report.md`. Чат исполнителя
  архитектору не виден (2026-09-26: отчёт T2.2 остался в чате, приёмка шла вслепую).
- В каждом ТЗ — раздел «Куда сдавать» с этим путём. Папку отчётов можно писать в любой задаче.
- Если правила нет — сначала записать его на доску задач проекта и в `AGENTS.md`.

## Запуск (Claude Code)

`Monitor` (отложенный — `ToolSearch select:Monitor`), сразу после выдачи ТЗ:

```
Monitor(
  description = "сдача исполнителей в <проект>",
  timeout_ms  = 1800000,
  command     = 'py -X utf8 "<этот скилл>/scripts/watch-executors.py" "<папка проекта>"'     # Windows
  # Mac: 'python3 "<этот скилл>/scripts/watch-executors.py" "<папка проекта>"'
)
```

Основная версия — `scripts/watch-executors.py` (Python, только стандартная библиотека, одна на Windows и Mac;
пути с кириллицей и пробелами — в кавычках). `scripts/watch-executors.sh` — старая мак-версия на zsh,
оставлена для мака, поведение и вывод те же. Переменные окружения (`WATCH_WIP=1`, `WATCH_INTERVAL`) —
префиксом перед командой (`WATCH_WIP=1 py -X utf8 ...`), если монитор запускается через Bash-инструмент.

События: только `СДАЧА <файл>` (2026-09-28: каждое событие — ход сессии архитектора со всем контекстом;
«В РАБОТЕ» и «КОММИТ» — по `WATCH_WIP=1`, когда без них нельзя).
Истёк таймаут — молча перезапустить, но не больше 4 раз подряд без сдачи (2 часа тишины): дальше не продлевать,
одной строкой пользователю «слежение остановил». Ни одного выданного ТЗ не ждём — слежение не включать.

**Приёмку — субагентом на дешёвой модели**, если в проекте есть `.claude/agents/acceptance-checker.md`:
он гоняет команды «Приёмки» из ТЗ и возвращает «прошло / не прошло» с цифрами. Решение и чтение диффа — за архитектором.
Так вывод команд и картинки не раздувают контекст архитектора.

## Приёмка при `СДАЧА`

1. Прочитать отчёт и ТЗ задачи.
2. `git status --short` + `git diff --stat`: изменены **только** файлы из «Можно трогать»
   (+ папка отчётов). Чужой файл тронут — не принято, как бы хорошо ни выглядело.
3. `git diff` по файлам задачи — прочитать, а не верить пересказу.
4. **Самому** прогнать команды из раздела «Приёмка» ТЗ (в свой scratchpad), не доверяя цифрам отчёта.
   Для видео — листы кадров, у стыков — 10–30 к/с; звук — `ebur128`, `astats`.
5. Решение:
   - **Принято** — коммит работы исполнителя отдельно и **по путям** (не `git add -A`),
     статус на доске «принято <дата>», строка в `STATE.md`.
   - **Не принято** — ТЗ `<ID>.<N+1>` с конкретными дефектами и критерием «готово, когда…»,
     статус на доске, коротко пользователю.
   - Дефект в данных архитектора (разметка, параметры) — исправить самому, отметить в отчёте пользователю.
6. Пользователю: что принято, что найдено, что дальше; ссылки — абсолютными путями.

## Не делать

- Не писать пользователю о событиях, которые не требуют приёмки или его решения, и о продлении монитора.
- Не опрашивать вручную (`sleep` + проверки каждый ход) — только фоновый монитор.
- Не принимать по отчёту без своих прогонов.
- Не коммитить незаконченную работу исполнителя (`В РАБОТЕ`) в свои коммиты.
- Не править файлы исполнителя во время его работы — только через ТЗ.
