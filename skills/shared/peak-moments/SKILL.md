# Пиковые моменты в видео

Скрипт только читает видео и пишет таблицу. Ничего не режет и не перекодирует.
Проверен на 26 реакциях и 36 TikTok-исходниках (youtube-shorts-cs, ТЗ T1 и T1.1, 2026-09-25).

## Команды

Запускать из корня проекта (ffmpeg ищется: `$FFMPEG` → `./bin/` → PATH, Homebrew не предлагать):

```
python3 <скилл>/scripts/peak_moments.py reaction "<папка или файлы>" --csv out/reaction_peaks.csv
python3 <скилл>/scripts/peak_moments.py source   "<папка или файлы>" --csv out/source_peaks.csv [--curve out/curve.csv]
```

- Папки обходятся рекурсивно (`.mp4 .mov .m4v .mkv .webm`).
- Без `--csv` таблица идёт в stdout. Сводка и ошибки идут в stderr, код выхода 1 при любой ошибке.
- CSV в UTF-8 с BOM (Excel открывает без кракозябр), время в секундах с 2 знаками.
- Битый файл не роняет прогон: он попадает в список ошибок.
- Встроенная проверка инвариантов идёт на каждом прогоне (см. ниже). Если проверка говорит «ок», это не значит «пики хорошие»: смотреть глазами всё равно надо.
- Скорость на Intel i9: 26 реакций по ~40 с ≈ 12 с, 36 исходников ≈ 45 с (4 потока ffmpeg).
- Повторный прогон даёт побайтово тот же результат.

## Что выдаёт

**reaction**: `file, fragment, start, end, duration, peak, score, rank`. Одна строка — один отрезок.
- `score` 0–1 нормирован **внутри файла** (лучший пик файла = 1), поэтому сравнивать `score` между файлами нельзя.
- Отрезки одного файла не пересекаются, пики разнесены на ≥ 3 с, отрезков не больше 6 на файл.

**source**: `file, duration, width, height, orientation, peak, peak2, peak_score, method, cut_start, cut_end`. Одна строка — один ролик.
- `method`: `audio+motion` / `audio` (статичная картинка) / `motion` (нет звука или тишина).
- `cut_start..cut_end` — окно 20 с, пик на 65% окна (подводка длиннее развязки). У края ролика окно упирается в границу. Ролик короче 15 с — окно = весь ролик.
- `--curve` пишет кривую активности 0..1 с шагом 0,1 с. По ней можно найти и вырезать «тихую середину» длинного ролика.

Все пороги — константы в начале скрипта, с комментариями.

## Как считает

**Движение**: ffmpeg `scene_score` на 4 кадра/с при ширине 160 px, сглаживание по 3 отсчётам (одиночный дёрганый кадр не даёт пик).
**Громкость**: RMS по окнам 100 мс (`astats`), в линейной амплитуде, а не в дБ: в дБ пики сплющиваются.
**Исходник**: 0,6 × громкость + 0,4 × движение, каждая нормирована min–max по зоне анализа.

## Уроки, которые зашиты в код, — не «упрощать» обратно

1. **Ложный пик на границе окна.** Если искать максимум только внутри разрешённой зоны, её первый отсчёт на спаде движения выглядит пиком. На старте записи модель всегда двигается, поэтому у 15 из 26 реакций «лучший момент» стоял ровно на 0,50 с. Лечится так: пик — **строгий** локальный максимум, соседи берутся настоящие, и у реакций оба соседа должны быть внутри окна.
2. **`score` нормировать по лучшему настоящему пику**, а не по максимуму кривой. Максимум кривой может лежать на отброшенной границе, и тогда в файле нет отрезка с `score = 1`.
3. **Деление соседних отрезков.** Сначала граница ставится в пропорции 1,5 : 2,5, затем сдвигается так, чтобы обоим отрезкам хватило 2 с. Без сдвига лучший пик у края окна получал 1,87 с и молча выбрасывался.
4. **Хвост исходника (1 с) не брать.** Громкая концовка или склейка TikTok побеждала: пик выпадал на последнюю секунду, и реакции после него «некуда развернуться».
5. **Хвост реакции (5 с) не брать.** Там служебный жест «в комменты», одинаковый во всех дублях.
6. **Уникализированные копии идут с другой скоростью.** Файл в `Unique` был на ~3% длиннее оригинала (42,0 с против 40,9 с). Тайминги, снятые с оригинала, для копии надо пересчитывать.
7. **Поворот телефонного видео**: ширину и высоту берём с учётом `rotation`, иначе вертикальное видео числится горизонтальным.

## Проверка глазами (обязательно перед «готово»)

Агент не видит видео и не слышит звук. Выбрать 5 случайных строк и собрать одну картинку-лист:

```
<ffmpeg> -v error -ss START -t DUR -i FILE -vf "fps=2,scale=200:150:force_original_aspect_ratio=decrease,pad=200:150:(ow-iw)/2:(oh-ih)/2,tile=8x1" -frames:v 1 row_N.png
<ffmpeg> -i row_1.png … -i row_5.png -filter_complex vstack=inputs=5 sheet.jpg
```

Для реакций `START..END` берётся из строки, для исходника — `peak−2 … peak+2`. Один лист на 5 строк стоит ≈ 2–3 тыс. токенов.
Пики в конце ролика часто оказываются мемом-панчлайном, а не ошибкой: сначала посмотреть, потом решать.
Звук по листу не проверить. Так и писать в отчёте.

## Грабли при запуске

- Пути с пробелами (`tiktok videos`, `CS СНГ`) в циклах `while read` на zsh/bash ломаются. Перебирать файлы из Python или брать разделитель-табуляцию.
- В zsh строка `echo ====` падает (`=` раскрывается). Для разделителей в выводе использовать `---`.
- Фильтр `drawtext` в сборке ffmpeg от evermeet падает, поэтому подписей на листах нет. Сверяться по порядку строк.
