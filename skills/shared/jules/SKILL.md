# Jules

Jules (jules.google) — асинхронный агент Google для кода. Берёт репозиторий с GitHub, работает на своей
временной машине, сдаёт изменения PR-ом. Модель — Gemini (на Pro — 3.x Pro). Считается по подписке Google
AI Pro, **не по лимитам Claude**. В связке: **Claude — ТЗ и приёмка, Jules — исполнение** (скилл `agent-workflow`).

Пометки: **[проверено]** — на деле 2026-10-16 (пилот в smm-planner); **[док.]** — из документации Jules,
не проверялось. Документация: jules.google/docs (из облачных сессий Claude не открывается — прокси режет).

## Лимиты и что входит

- Pro: **100 задач за скользящие 24 ч, 15 одновременно** [док.; счётчик «Daily session limit N/100» — в
  интерфейсе, проверено]. Бесплатно: 15 и 3. Сообщение в идущую задачу новую задачу **не тратит** [проверено].
- Antigravity и Gemini CLI у владельца лимиты подписки не берут (его слова, 2026-10-16); Jules — берёт
  (значок PRO, модель Gemini 3.1 Pro) [проверено].
- **Ключ Jules API ≠ ключ Gemini API.** Ключ Jules на Gemini API отвечает 403 SERVICE_DISABLED [проверено].
  Для текстов/рутин через Gemini нужен свой ключ (AI Studio или включённый Gemini API в проекте Cloud).

## Что отдавать, что нет

Отдавать — задачи по коду, которые проверяются запуском:
- тесты (unit, e2e на заглушках), скрипты по образцу, механические правки, мелкие хвосты из `STATE.md`;
- задачи по расписанию (раз в день/неделю/месяц): прогон всех тестов на свежем `main` и PR с исправлением.

Не отдавать:
- **рутины на данных сервера** (посты, сбор, публикация): Jules не видит сервер, а давать его машине
  SSH-ключ, токены площадок, VPN — нельзя. Расписание только день/неделя/месяц, точного часа нет [док.].
  Результат Jules — PR, а не файл на сервере;
- архитектуру, промпты ролей, пороги, выбор решений — это Claude;
- ничего с секретами: переменные окружения Jules **видит агент** (предупреждение в настройках).

## Подготовка репозитория (один раз, человек)

1. Jules → подключить GitHub, дать доступ **только нужным** репозиториям (GitHub → Settings → Applications →
   Google Labs Jules → Configure).
2. Codebases → репозиторий → **Configuration → Environment**:
   - **Setup script** — установка того, чего нет на машине. Предустановлено: Ubuntu, Python 3.12, Node 22,
     Go, Java, Rust, Docker, pytest, ruff, chromedriver. **Playwright и браузера нет** — для e2e:
     ```
     pip install -q pillow==<версия> playwright==<версия из requirements.txt>
     python -m playwright install --with-deps chromium
     ```
     **Run and Snapshot** — прогон и снимок машины; дальше все задачи репозитория стартуют со снимка [док.].
     Без снимка Jules каждый раз ставит всё сам — задача на 10+ минут дольше [проверено].
   - **Environment variables** — не класть секреты (видит агент).
   - **Network access** — по умолчанию включён.
3. Jules читает `AGENTS.md` и `README.md` как подсказки — в проекте по стандарту `AGENTS.md` уже ведёт в `CLAUDE.md`.
4. Settings → **Git commit authoring**: по умолчанию «Co-authored (Jules + User)», Jules — автор коммитов.
   При правиле «без следов ИИ» сливать PR **squash-ом** от своего имени (скилл `git-release-discipline`).
5. Settings → **API Key** — ключ для `scripts/jules.py`. Не больше 3; ключ, найденный в открытом доступе,
   Google отключает сам [док.]. Хранить в переменных окружения среды, не в чате и не в git.

## ТЗ для Jules

Шаблон и правила — скилл `agent-workflow`. Для Jules обязательно:
- **цель** одной фразой и **ровно какие файлы** создать/менять; всё прочее — нельзя;
- **что прочитать** (файлы и строки) и **образец** в репозитории, по которому делать;
- **проверка**: команда, ожидаемый вывод, код выхода; вывод — целиком в описание PR;
- **запреты**: выкладка, сервер, `.env`, промпты, сборочные файлы в git (`out/` и т. п. — вернуть перед коммитом);
- нашёл ошибку вне задачи — не чинить, описать в PR.

Хранить ТЗ — `docs/ГГГГ-ММ-ДД_<задача>-tz.md` проекта-заказчика (или проекта интеграции).

## Цикл: поставить → дождаться → принять

```
export JULES_API_KEY=…                                   # из окружения среды
S=…/_instruments/skills/shared/jules/scripts/jules.py
python3 -X utf8 $S sources                               # id репозитория: github/<owner>/<repo>
python3 -X utf8 $S new <owner>/<repo> docs/<…>-tz.md     # → id задачи; PR создастся сам
python3 -X utf8 $S wait <id>                             # фоном (run_in_background), до 70 мин, раз в минуту
python3 -X utf8 $S patch <id> <scratchpad>/jules.patch   # дифф + список файлов + ссылка на PR
```

Приёмка (не верить отчёту на слово — скилл `verify-before-claiming`):
1. Список файлов диффа = файлы из ТЗ. Лишнее — вернуть.
2. Прочитать код. Затем `git fetch origin refs/pull/<N>/head` и прогнать проверку из ТЗ у себя.
3. **Проверить, что проверка ловит поломку**: на время испортить то, что тест проверяет → должен быть FAIL →
   вернуть. На пилоте первая сдача была зелёной 36/36, но тестировала устаревшую сборку — поймано только так.
4. Замечания — в ту же задачу: `jules.py say <id> <файл>` (пронумеровать, у каждого — как проверить).
   Ждать снова `wait`; исправления придут в тот же PR.
5. Зелено и честно → человеку: «принято, сливаю squash-ом?» — сливать по «да».

Сроки на пилоте: первая сдача ~20 мин (без снимка окружения), доработка по замечаниям ~10 мин.

## API — что знать [проверено]

База `https://jules.googleapis.com/v1alpha/`, заголовок `X-Goog-Api-Key`.
- `GET sources` — подключённые репозитории.
- `POST sessions` — `{prompt, title, sourceContext:{source:"sources/github/o/r", githubRepoContext:{startingBranch}},
  automationMode:"AUTO_CREATE_PR", requirePlanApproval}`. Без `automationMode` PR не создаётся; план через API
  одобряется сам, если не `requirePlanApproval: true` (тогда `POST sessions/<id>:approvePlan`).
- `GET sessions/<id>` — `state` (`IN_PROGRESS`, `COMPLETED`, `FAILED`, `AWAITING_*`, `PAUSED`), `outputs`:
  `pullRequest.url` и `changeSet.gitPatch.unidiffPatch` (дифф целиком).
- `POST sessions/<id>:sendMessage {prompt}` — ответ пустой, реакция — в журнале.
- `GET sessions/<id>/activities?pageSize=30` — журнал. **pageSize больше 30 → пустой ответ `{}`** (замечено на 50
  и 100); страницы от старых к новым, дальше — `pageToken`.
- Задача из GitHub без API: метка `jules` на issue [док.].
- Расписание создаётся только в веб-интерфейсе (Planning → Scheduled Task), изменить нельзя — удалить и создать [док.].
- CLI `npm i -g @google/jules` требует вход через браузер; для агента API удобнее.

## Не нужно

Suggested Tasks (ищет только `TODO` в коде), Render-интеграция (если хостинг не Render), MCP-подключения Jules
(Linear, Supabase и т. п.) — пока нет задачи под них.
