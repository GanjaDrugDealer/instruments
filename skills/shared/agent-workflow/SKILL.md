# Разделение работы между агентами

Работа над проектом идёт **поочерёдно**, не одновременно. Одна папка,
агенты заходят по очереди. Два агента в одних файлах без блокировок
затирают друг друга молча — этого сценария нет.

## Граница: исполнение против понимания

Делить надо не по файлам и не по слоям кода, а по типу работы.

| Тип задачи | Кому |
|---|---|
| Прогнать сборку, прочитать лог, повторить до зелёного | Antigravity |
| Механическая правка по готовому образцу | Antigravity |
| Собрать факты: что в логе, какие флаги, где лежит | Antigravity |
| Прогнать тесты и принести вывод | Antigravity |
| Понять, **почему** не работает | Claude |
| Правки там, где ошибка молчаливая | Claude |
| Архитектурные решения | Claude |
| Написать ТЗ и принять работу | Claude |

**Тест перед делегированием:** могу ли я заранее написать, как выглядит
правильный результат? Могу — отдаю. Не могу — задача исследовательская,
делаю сам.

**Встречное правило:** если постановка ТЗ дороже самой правки — не отдавать.
Разбор плохой работы стоит дороже, чем сделать сразу.

Слабому агенту можно отдать правку и в самом чувствительном модуле, если ТЗ
звучит как «добавь в список X строку Y, прогони проверку, покажи дифф».
Это исполнение. «Разберись, почему отсеивается лишнее» — понимание,
не отдавать: найдёт правдоподобное объяснение, и оно будет неверным.

## Цикл: ТЗ → исполнение → приёмка

```
Claude пишет ТЗ  →  Antigravity исполняет  →  Claude принимает
   дорого,            дёшево,                  дорого,
   но один раз        сколько угодно итераций  но по диффу
```

Дорогие токены уходят в постановку и приёмку, а не в цикл
«собрал — упало — поправил — собрал».

**Приёмка идёт по диффу, а не по пересказу.** Дифф дёшев и не врёт;
пересказ исполнителя дорог и врёт.

### Как снять дифф

Git для приёмки не обязателен — во многих проектах его нет и не будет.
Универсальный способ одинаков для всех проектов:

```cmd
:: тот, кто выдаёт ТЗ, — ДО выдачи
python -X utf8 "C:\AI Projects\_Instruments\scripts\snapdiff.py" snap "<папка проекта>"

:: исполнитель при сдаче и принимающий при приёмке
python -X utf8 "C:\AI Projects\_Instruments\scripts\snapdiff.py" diff "<папка проекта>"
```

- Снимок ложится в `%LOCALAPPDATA%\agent-snapshots\<проект>\<дата_время>`,
  вне проекта. `diff` сравнивает с последним снимком, код выхода 1 — есть изменения.
- Пропускаются junction и симлинки (данные на другом томе не копируются),
  `.git`, `.venv`, `node_modules`, `__pycache__`, `secrets.json`, `.env`,
  файлы больше 5 МБ.
- Снимок не трогать и не пересоздавать исполнителю: новый `snap` сотрёт
  точку отсчёта для приёмки.
- Файл изменён вне списка ТЗ — работа не принята, как бы хорошо ни выглядела.

Если в проекте есть git — можно `git diff`, это равноценно. Но правило
формулируется через дифф, а не через git.

### Что должно быть в ТЗ

1. Список файлов, которые можно трогать. Остальные — нельзя.
2. Что именно сделать, в терминах результата, а не догадок.
3. Критерий готовности: какая команда должна отработать и что вывести.
4. Что показать по окончании: вывод `snapdiff.py diff` целиком.

Без критерия готовности исполнитель сдаст «вроде работает».

## Передача смены: STATE.md

Дифф фиксирует *что* сделано. Он не фиксирует *почему*, что пробовали
и отвергли, и что дальше. Для этого — один живой файл `STATE.md` в корне
проекта.

```markdown
## Сейчас
Что в работе, на какой стадии.

## Следующий шаг
Одна конкретная задача и кому она.

## Решено и закрыто
Факты, которые больше не проверяем.

## Открытые вопросы
Что непонятно, какие гипотезы.
```

Правило: **кто заканчивает смену — обновляет файл.** Это дёшево. Без него
каждый новый сеанс начинается с пересказа истории, а вот это дорого.

`STATE.md` — текущая страница, короткая. Длинные разборы и история —
отдельными датированными документами в `docs\`.

## Ограничения для слабого агента

Записывать в `GUARDRAILS.md` проекта:

- работать только по выданному ТЗ, файлы вне списка не трогать
- перед сдачей прогнать проверку проекта, без зелёного не сдавать
- архитектурных решений не принимать: упёрся — вернуть вопрос
- удаление файлов, откат чужих правок (`git reset`, `git checkout`, если git есть) — только с подтверждения
- сдавать вывод `snapdiff.py diff` целиком, своими словами не пересказывать

Antigravity по умолчанию выполняет команды без спроса
(`CASCADE_COMMANDS_AUTO_EXECUTION_EAGER`), поэтому запреты должны быть
записаны, а не подразумеваться.

## Общие данные

Профили, базы и `.env` лежат в одном экземпляре, вне репозитория и снимков.
Если оба агента запустят приложение на одном профиле — база побьётся.
Прогоны по очереди, либо каждому свой профиль.
