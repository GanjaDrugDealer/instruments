# Слежение за задачами проекта

Пользователь не должен пинать исполнителя. Встал в ожидание — сразу включи слежение;
событие пришло — сам прочитай и начни работу.

## Главное: молчать, если не касается

Владелец 2026-09-28: «не пиши сюда, если задача не для тебя». Каждое событие монитора приходит в чат
как отдельный ход — отвечать на него текстом **нельзя**, если оно не про мою роль:
- чужие задачи, отчёты и коммиты других агентов, правки STATE не про меня — **ни слова**;
- продление монитора (истёк таймаут, «СЛЕЖУ: …») — перезапустить **молча**;
- мои собственные правки, вернувшиеся событием, — молча.

Пишу пользователю только когда: подхватил **свою** задачу / сдал её / нашёл то, что ломает мою работу
или требует его решения. Одна-две строки, по делу.

## Запуск (Claude Code)

Инструмент `Monitor` (отложенный — загрузить через `ToolSearch select:Monitor`):

```
Monitor(
  description = "задачи архитектора в <проект>",
  timeout_ms  = 1800000,                    # максимум 30 мин
  command     = 'zsh "<этот скилл>/scripts/watch-tasks.sh" "<папка проекта>"'
)
```

- **Каждое событие — это ход сессии со всем её контекстом, то есть токены.** Поэтому слежение узкое (2026-09-28):
  по умолчанию только `docs/tasks` без папки отчётов, без STATE и коммитов.
- **Хвост на старте** (2026-10-03): при запуске скрипт сам выдаёт «ЗАДАЧА ЖДЁТ <файл>» по своим задачам без отчёта и без
  «принято» на доске — то, что выдали, пока слежение было выключено. Брать в работу как новую задачу.
- **Всегда задавай свой фильтр** `WATCH_MATCH` — часть имени файла твоих задач (Контентщик — `_CM`, монтажёр — `_T2`):
  `command = 'WATCH_MATCH=_CM zsh "<этот скилл>/scripts/watch-tasks.sh" "<папка проекта>"'`.
  Правки доски, чужие ТЗ и отчёты тогда вообще не будят сессию. `WATCH_COMMITS=1` — только если без коммитов нельзя.
- Интервал: `WATCH_INTERVAL=10` (секунды). Локальная проверка — дёшево, 5–10 с нормально.
- Первая строка `СЛЕЖУ: …` — подтверждение, что встал. Дальше строки
  `КОММИТ <hash> <сообщение>`, `НОВЫЙ ФАЙЛ`, `ИЗМЕНЁН`, `УДАЛЁН`.

Другие агенты (Antigravity и т.п.) — тот же скрипт в фоновом процессе, читать его вывод.

## Что делать при событии

0. **Не моё — молчать.** Событие не про мою роль (чужие задачи, STATE, коммиты других исполнителей, продление монитора) —
   пользователю ничего не писать (владелец 2026-09-28: «не пиши сюда, если задача не для тебя»).
1. Своё ли это изменение? Правки, которые исполнитель сделал сам (или коммит архитектора,
   забравший сданную работу без нового ТЗ), — не задача; молча ждать дальше.
2. Иначе: `git show --stat <hash>` / прочитать изменённый файл задачи → найти, что выдано **мне**
   (доска задач, статус «выдано», новые пункты в ТЗ моей задачи, ответы на мои вопросы).
3. Коротко сказать пользователю, что подхватил и что делаю, — и делать. Не спрашивать «начинать?».
4. Сдача — по правилам проекта (обычно: список файлов, вывод проверок, листы).
   **Отчёт — всегда файлом, не только в чат.** Архитектор работает в другой сессии и чат исполнителя
   не видит (2026-09-25 архитектор проверял T2.2 вслепую: «отчёт недоступен»). Писать `<задача>_REPORT.md`
   туда, куда ТЗ разрешает (папка отчётов проекта; если её нет — рядом с тестовыми файлами в `OUT_DIR`/scratchpad),
   с абсолютными путями ко всем листам и status.csv. Пользователю — полный путь к отчёту.

## Продление

Монитор живёт максимум 30 минут. На уведомлении об истечении — молча перезапустить тем же вызовом, не спрашивая
и не сообщая пользователю. **Но не бесконечно:** каждое продление — тоже ход. 4 продления подряд без своих событий
(2 часа тишины) — не продлевать, одной строкой: «слежение остановил, скажите „жди“, когда будет задача».
Задача сдана, а новой нет — слежение не включать; сессию лучше закрыть (одна задача — одна сессия). Слежение живёт, пока открыта сессия: закрыли приложение — после перезапуска
включить заново (если пользователь снова говорит «жди»).

## Не делать

- Не писать пользователю о событиях, которые не про мою роль, и о продлении монитора. Пишем только:
  подхватил свою задачу / сдал её / нашёл то, что ломает мою работу.

- Не опрашивать вручную (`sleep` + проверка в каждом ходе) — это тратит ходы; только фоновый монитор.
- Не реагировать на каждый шум: изменения в коде/данных без новой задачи — не повод начинать работу.
- Не трогать чужие файлы задач/STATE: их ведёт архитектор.
