# Antigravity CLI (`agy`) по подписке

`agy` — официальный консольный агент Google Antigravity. Внутри подписки Google AI Pro он даёт Gemini 3.8 Flash
(low/medium/high), Claude Sonnet/Opus 4.6, GPT-OSS и генератор картинок — без ключа API и без оплаты за токены.
Опыт — проект smm-planner (с 19.10.2026 на сервере: картинки к постам, фактчек, теневой автор).

Готовое в этой папке:
- `scripts/agy.py` — вызов из кода (только stdlib): `usage`, `text` (JSON по схеме), `image`. Копировать в
  `scripts/` проекта, не ссылаться. Проверка — `scripts/test_agy.py` (поддельный agy, без сети).
- `references/accounts.md` — какие аккаунты есть у пользователя, какой брать новому проекту, как делить квоту.
- `references/stream-json.md` — формат вызова и ответа, ошибки, замеры расхода.
- `references/server.md` — agy на Linux-сервере: пользователь, туннель на постоянный адрес, ufw, обёртка,
  второй аккаунт, помощник через sudo, вход по ссылке.

## 1. Правила против бана — читать первым

Баны Antigravity (форум Google, разбор 21.10.2026): за **сторонние программы на OAuth Antigravity** и, по жалобам,
за **перебор аккаунтов** и **оплату подписки с другого аккаунта**. Вход с нескольких устройств причиной не значится.

1. **Только официальный `agy`** (и само приложение Antigravity). Никаких OpenClaw, OpenCode, «antigravity-proxy»,
   плагинов-мостов, OpenAI-совместимых прокси поверх входа Antigravity, чужих клиентов с его токеном. Токен
   (`antigravity-oauth-token`) не копировать в другие программы. Вход Gemini CLI в чужих программах Google тоже
   запрещает — мосты к Gemini CLI не берём.
2. **Свой код зовёт только сам `agy`** (`agy -p …`) как обычную программу — так делает `scripts/agy.py`. Не
   разбирать протокол agy, не ходить в его API напрямую.
3. **Один постоянный адрес на аккаунт.** Google смотрит страну и адрес: из РФ входа нет. Сервер — только через
   туннель на один выход; на ПК — тот же выход через VPN (так сделано у ganjadrugdealer: сервер и ПК — один
   77.246.106.173). Не скакать по странам и VPN-узлам.
4. **Подписка оплачена на том же аккаунте**, которым входят. Семейный доступ, «оплатил другой аккаунт» — не берём.
5. **Несколько аккаунтов — ничем не связаны:** разные выходы, разные установки agy (`installation_id`), разные
   `machine-id` и имя хоста, отдельный профиль браузера для входа. Ферму аккаунтов «по очереди ради квоты» не
   делаем (решение 19.10: риск связанного бана); второй аккаунт — только когда одного не хватило по замеру.
6. **Не переключаться на другой аккаунт по 429.** При разбане Google требует подтвердить: «bypassing system
   measures or circumventing usage limits is prohibited»; второе нарушение — бан навсегда. У каждого аккаунта своё
   назначение (`references/accounts.md`). Где два аккаунта делят одну работу (картинки smm) — **бюджет заранее**:
   аккаунт набрал свою долю в окне — следующая задача идёт другому, задолго до предела; 429 всё же пришёл — блок
   до сброса и запасной не-Google путь, а не другой аккаунт сразу после ошибки.
7. **Новый проект — не новый вход.** Подключать к уже вошедшей установке (тот же пользователь и выход), а не
   входить тем же аккаунтом ещё с одного адреса или машины.
8. Условия и сбор данных при первом запуске принимает человек сам. Без `--dangerously-skip-permissions` в
   автоматике — агент без инструментов (п. 5) их не просит.

## 2. Установка

Официальные установщики (сами сверяют SHA-512 скачанного; доверенный источник — только `antigravity.google`):

| Где | Команда | Куда ставит |
|---|---|---|
| Linux, macOS (и Intel) | `curl -fsSL https://antigravity.google/cli/install.sh \| bash` | `~/.local/bin/agy` |
| Windows, PowerShell | `irm https://antigravity.google/cli/install.ps1 \| iex` (на ПК ещё не ставили) | `%LOCALAPPDATA%\agy\bin\agy.exe` |
| Windows, cmd | `https://antigravity.google/cli/install.cmd` | то же |

- Ключи установщика: `--skip-path` (не трогать `PATH` в профиле оболочки), `--skip-aliases`.
- Mac пользователя — без Homebrew (скилл `mac-standalone-tools`): официальный `install.sh` годится, он сам кладёт
  бинарник в `~/.local/bin`. Скачивание и установку — спросить у человека (что, откуда, ~220 МБ).
- Проверка: `agy --version` (на сервере 19.10 — 1.4.2), `agy models`, обновление — `agy update`.
- Сервер: ставить **от отдельного пользователя** (`sudo -u <user> -H bash -c 'curl … | bash'`), второй аккаунт —
  свой пользователь со своей копией бинарника (копировать бинарник можно, папку `~/.gemini` — нельзя).
- Данные: `~/.gemini/antigravity-cli/` — `antigravity-oauth-token` (вход, 600; на ПК вход может лежать в
  хранилище ключей ОС), `installation_id`, `settings.json` (`trustedWorkspaces` — доверенные папки),
  `brain/<разговор>/` (файлы разговоров, сюда же ложатся картинки), `log/`.

## 3. Вход

- **ПК:** первый `agy` открывает браузер, вход Google. Включить VPN на выход этого аккаунта **до** запуска.
- **Сервер (SSH):** agy печатает ссылку `https://accounts.google.com/…` и ждёт код. Ссылку открыть на ПК в
  браузере **через тот же выход**, что у сервера (VPN или отдельный профиль Chrome с SOCKS через туннель), войти,
  скопировать код со страницы `antigravity.google`.
- **Код вводить на ПК, не вставкой в окно tmux через SSH** — так он портится («Malformed auth code»). Рабочий
  способ: agy запущен в `tmux` на сервере, код человек вводит на ПК в скрытую строку (`getpass`), скрипт шлёт
  его `tmux send-keys -l -- <код>` + `Enter` (образец — `send_code()` в smm-planner `scripts/server_agy2.py`).
- Меню выбора входа — стрелки/`Enter` через `tmux send-keys`; экран — `tmux capture-pane -p -J`. Ссылка
  переносится по строкам — склеивать.
- Тариф виден только в окне agy: `/usage`, строка «(Antigravity Starter Quota)» = Starter, даже если Pro
  куплен (было у ganjacsdealer 19–21.10 — аккаунт заменили). После входа — сразу проверить.
- Выход — `/logout` в окне agy. Ключ API (`GEMINI_API_KEY`, `"modelProvider": "gemini"`) — это оплата по токенам,
  не подписка: нам не нужен.

## 4. Квоты

`agy -p /usage --print-timeout 45s` — бесплатно, строки через TAB:

```
Gemini Models          Weekly Limit Remaining     87%   2026-10-26T18:35:26Z
Gemini Models          Five Hour Limit Remaining  91%   2026-10-20T18:40:09Z
Claude and GPT models  Weekly Limit Remaining     98%   2026-10-26T20:03:51Z
Claude and GPT models  Five Hour Limit Remaining 100%   2026-10-20T21:09:55Z
```

- Две группы: **Gemini** и **Claude and GPT**; у каждой окно 5 ч и неделя. У Starter строки «Five Hour» нет.
- **Квота — на аккаунт**, общая для всех его входов: ПК, сервер, приложение Antigravity. Чужой проект на том же
  аккаунте ест квоту всех остальных.
- **У картинок своя скрытая квота**, в `/usage` её нет: на Pro — ~12 файлов за окно 5 ч (19.10: 429 после 12-го,
  сброс ровно через 5 ч от первой картинки окна), на Starter — ~7 в неделю, потом 429 на дни. Один вызов иногда
  даёт 2–4 файла (генератор сам рисует варианты `v2`, `v3`) — считать файлы в `brain/<разговор>/`, а не вызовы.
  Свой бюджет держать с запасом (в smm — 8 из 12). Неудачные попытки едят текстовую квоту Gemini (Starter ~4 %).
- **Текст на Pro — почти без ограничений** (Gemini Flash квоту почти не двигает): тесты гонять на тексте и на
  подставных процессах, настоящую картинку на тест — только по слову человека.
- Расход (замеры 19–20.10, Pro): Gemini 3.8 Flash — пост с источниками ~18–35 тыс. токенов, квота почти не
  двигается; Claude Sonnet 4.6 — 3 % окна 5 ч и 2 % недели за 18 тыс. токенов → Claude в agy — только аварийно.
  На Starter Gemini — 3 % недели за такой же вызов.
- **Сторож бюджета:** перед вызовом смотреть `/usage` своей группы (кэш 10 мин), ниже порога (25 %; фоновые
  задачи — 50 %) — не звать. Так оставляется запас тем, кто делит аккаунт.

## 5. Вызов из кода: «вход → JSON по схеме»

```
agy -p= --input-format stream-json --output-format stream-json \
    --model gemini-3.8-flash-medium --effort medium --json-schema '<схема строкой>' --print-timeout 280s
stdin:  {"event":"user","message":{"content":"<весь промпт>"}}
ответ:  последняя строка {"event":"result","result":{"status":"SUCCESS","response":…,"usage":…,"num_turns":1}}
```

`scripts/agy.py text` делает это целиком: сторож, замок, блок после 429, разбор, журнал. Главное (подробно —
`references/stream-json.md`):

1. Промпт — только через stdin в stream-json: в аргументе больше 128 КБ не пролезет, а в текстовом режиме stdin
   agy молча игнорирует.
2. **Инструментов нет — сказать дважды, в начале и в конце промпта:** «весь контекст ниже, ничего не открывай,
   не ищи и не запускай, сразу ответ JSON по схеме». Иначе Gemini лезет в `ls`/`find`, получает отказ и отвечает
   пусто (20.10 — 22 из 30 вызовов; 21.10 — снова при одном запрете в начале). Всё нужное кладёт в промпт код.
3. Ответ: `result.structured_output` или `result.response` (часто JSON строкой); пусто, а был `finish` с
   `parameters` — ответ там. Итоговый статус («чисто/ошибки») считает код по полям, не модель.
4. Один вызов на задачу: у каждого вызова наценка ~11,8 тыс. входных токенов (системный промпт agy).
5. `--print-timeout` на 20 с меньше таймаута процесса; обычная задача — 300 с, длинная на `high` — до 600 с.
6. **429 искать только в ошибках** (stderr, `result.error`), не в тексте ответа: «429» бывает внутри числа
   токенов (14290) → ложный блок на 6 ч. Признаки: `429`, `RESOURCE_EXHAUSTED`, `exhausted your capacity`.
7. 429 → файл блока до сброса (из `/usage` или «reset after 4h29m54s»; не нашли — 6 ч), пока он есть — agy не
   звать. На другой аккаунт по 429 не переключаться (правило 6 раздела 1).
8. **Одна задача за раз** на аккаунт — замок (`flock`), общий у всех помощников этого аккаунта (`--lock`).
   **Картинки — приоритет** (решение пользователя 21.10): картинка, ждущая замка, останавливает идущий текстовый
   вызов, новые тексты не встают в очередь, пока она ждёт. **Остановленный текст продолжается сам** после
   картинок: ждёт замок и запускается заново (с начала; в ответе `preempted: N`), код 5 — только если картинки
   шли дольше `wait_s` (час). Чужому помощнику картинок текст уступает по `AGY_YIELD_TO` (шаблон `pgrep -f`).
   То же правило — для работы агентов: пришла задача на картинки — отложить остальное, сделать картинки и
   вернуться к отложенному.
   **Долгие задачи по коду** (агент с инструментами, часы) не перезапускать, а замораживать: служба
   `agy-code-<проект>-<имя>` (или `agy-dev-*`) через `systemd-run`; помощник картинок рисует сначала аккаунтом без
   кода, а если код идёт на всех — `systemctl freeze` задачи этого аккаунта на время картинки и `thaw` в `finally`
   (cgroup v2, systemd ≥ 246). Проверено 21.10: 150 с заморозки посреди работы — задача доделана `SUCCESS`.
   Упала всё же — продолжить тот же разговор: `agy -p "продолжи с места остановки" --conversation <id>`
   (`conversation_id` — в первой строке лога stream-json).
9. agy запускать из доверенной папки (`trustedWorkspaces` в `settings.json`; на сервере — `~/work`): так agy не
   спрашивает, доверять ли папке, и видит файлы, которые ему кладут (образец картинки).
10. Приёмка: код, который написал agy (Gemini), принимать по диффу самому — 20.10 исполнитель «подделал» формат
    agy в своих тестах, и тесты были зелёные.

## 6. Картинки

```
agy -p "<промпт картинки>" --model gemini-3.8-flash-low --effort low --output-format json --print-timeout 280s
```

- Ответ — JSON с `conversation_id`; картинка — новейший `*.jpg|png|webp` в
  `~/.gemini/antigravity-cli/brain/<conversation_id>/`. Скопировать к себе; `brain/` чистить (старше 14 дней).
- **Образец (лого) — файлом в рабочей папке agy**, и в промпте: «Pass the file <путь> to the image generation
  tool as an input image; do not modify the logo» (генератор получает его файлом — так работает с 19.10).
- 429 генератора не виден в ответе: искать `RESOURCE_EXHAUSTED` в
  `brain/*/.system_generated/logs/transcript.jsonl`, изменённых после старта вызова, оттуда же «reset after …».
- `low`/`low` — меньше рассуждений вокруг генератора, меньше расход Gemini.
- Нужна страховка — запасной генератор вне Google (в smm-planner — Cloudflare Workers AI FLUX.2, только stdlib).
- `scripts/agy.py image <файл> [--ref лого.png] < промпт`.

## 6а. Чтение картинок и файлов (проверено 28.10, vk-dzen)

- Картинки читаются тем же `scripts/agy.py text`: файлы лежат в доверенной рабочей папке (`AGY_WORKDIR`), в
  промпте — их пути и запрет всего, кроме `view_file`: «можно ТОЛЬКО открыть view_file перечисленные файлы, ничего
  больше; после — сразу JSON по схеме». `tools_used: true` в ответе тут норма.
- Точность: скрин ответа Глифа переписан дословно, выделение цветом отмечено верно. Gemini Flash medium: 1 картинка —
  ~50-60 с и ~27 тыс. токенов, недельная квота Gemini почти не двигается.
- Пачки — по 5-8 картинок с контекстом (сообщения вокруг скрина), не по одной: наценка ~12 тыс. токенов на вызов.
  Просить переписать, что видно (текст, выделенное, пункты формы), а выводы делать самому.
- Образец — vk-dzen `src/screens_agy.py` (пачки по обсуждениям, продолжение с места остановки, сводка в md).

## 7. Сервер — коротко (подробно `references/server.md`)

- Отдельный пользователь на аккаунт, `~/work` — доверенная папка, вход в его `~/.gemini`.
- В сеть он ходит **только через туннель** на постоянный выход (autossh → SOCKS `127.0.0.1:<порт>`); напрямую —
  `REJECT` в `ufw before.rules` по `--uid-owner`. Обёртка `/usr/local/bin/agy-<имя>`: `cd ~/work`, прокси
  `socks5h://…`, запуск от этого пользователя.
- Второй аккаунт — свой пользователь, свой туннель и выход, свои `machine-id` и имя хоста (`unshare -m -u`).
- Другие службы зовут agy через помощник от root по `sudoers` (одна строка на одну программу); промпт и схема —
  содержимым через stdin (пользователю agy файлы проекта не видны).
- Память: бинарник 220 МБ, вызов — сотни МБ; на сервере с 2 ГБ — одна задача за раз, долгие — `systemd-run -p
  MemoryMax=900M`.

## 8. Чек-лист: agy в новый проект за 15 минут

1. **Аккаунт** — по `references/accounts.md`: какой свободен, чья квота; новый вход не заводить (правило 7).
2. **Где работает:** уже есть установка на сервере → п. 4; нужен на ПК → п. 3.
3. **ПК:** VPN на выход аккаунта → официальный установщик (спросить человека) → `agy` → вход → `/usage`
   (не Starter?) → `agy models`.
4. **Сервер:** `sudo <обёртка> -p /usage --print-timeout 45s` отвечает? `curl` от пользователя agy напрямую —
   закрыто, через прокси — нужный выход (`references/server.md`, «Проверка»).
5. Скопировать `scripts/agy.py` (и `test_agy.py`) в `scripts/` проекта; `python -X utf8 scripts/test_agy.py` —
   зелёный.
6. Настроить: `AGY_CMD` (путь к agy или обёртке), `AGY_HOME`, `AGY_STATE` (своя папка проекта), `AGY_LOCK`
   (общий замок аккаунта), `AGY_YIELD_TO` (чей помощник картинок рядом), `AGY_EXPECT_IP` (на ПК), порог
   `min_pct`. Таймаут у вызывающего кода — с запасом на очередь картинок (`wait_s` + `timeout_s`); выход 5 —
   «картинки шли больше часа», повтор позже, не ошибка.
7. Пробный вызов: `echo '{"prompt":"Ответь JSON {\"ok\":true}. Инструментов нет.","schema":{"type":"object"}}' |
   python scripts/agy.py text` → `ok: true`; `/usage` до и после — расход в журнал решений проекта.
8. Записать в справочник проекта: аккаунт, выход, где вызов, порог, файл блока; в `.gitignore` — папку состояния.

## 9. Ошибки → что делать

| Признак | Причина | Делать |
|---|---|---|
| `status: SUCCESS`, ответ пустой, `tools_used` | модель полезла в инструменты | запрет инструментов в начале **и** в конце промпта |
| нет строки `event=result` | вход слетел, сеть, таймаут | `/usage`; нет строк квоты → вход заново (п. 3) |
| 429 / `RESOURCE_EXHAUSTED` | квота группы или картинок | блок до сброса, не повторять в цикле |
