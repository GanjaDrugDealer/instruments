# Скриптование на русскоязычной Windows

Машина пользователя — Windows с русской локалью, консоль в CP866, PowerShell 5.1.
Это ломает почти всё, что кажется очевидным. Правила ниже добыты отладкой,
не выведены из документации. Они не зависят от агента и его инструментов.
Инструменты Claude (Desktop Commander, мост) — в скилле `desktop-commander-bridge`.

## Правило 1: не передавай команды строкой, пиши файл

Инлайн-команда через `-Command "..."` проходит через несколько слоёв
экранирования: теряются `$переменные`, ломаются вложенные кавычки и обратные
кавычки, `python -c "..."` разваливается почти всегда.

Вместо этого: запиши скрипт в файл → запусти его одной строкой.

```
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File "...\job.ps1"
python -X utf8 "...\job.py"
cmd /c "...\job.bat"
```

Вложенные кавычки в `cmd /c "... & ..."` разваливаются так же, как в PowerShell.
Временные скрипты — вне папки проекта (`%TEMP%`).

## Правило 2: PowerShell — только латиница

Файл `.ps1` без BOM PowerShell 5.1 читает как ANSI. Кириллица в строках и
`Write-Output` превращается в мусор и роняет парсер с `UnexpectedToken`.
Кириллица в инлайн-команде тоже искажается по дороге — сравнение строк
промахнётся, а записанный в файл текст окажется битым.

**Всё, где нужна кириллица, — на Python** с `-X utf8`. Python читает исходник
как UTF-8, `-X utf8` чинит и вывод. Комментарии на кириллице в `.ps1` парсер
переживает, строки — нет.

## Правило 3: вывод консоли может прийти битым

Даже когда скрипт отработал верно, кириллица в выводе может прийти как
`2026 ????` или `╨Ъ╨╛╨╜`. Это косметика консоли, а не ошибка выполнения.
Помогает `PYTHONIOENCODING=utf-8` перед запуском Python.

- Проверять содержимое файла — Python-однострочником с `encoding="utf-8"`,
  а не `Get-Content` без `-Encoding UTF8`.
- Никогда не строй следующий путь из битого вывода: возьми настоящее имя
  листингом папки.

**Лог смешанной кодировки.** Если в один файл пишут и `cmd` (CP866), и Python
(UTF-8) — так получается у любого сборочного батника, — многие читалки файлов
откажутся его открыть как текст. Перекодируй хвост (заведи скрипт один раз
в начале работы, а не когда упрёшься):

```python
# tail.py <файл> [строк] -> tail.txt в чистом UTF-8
import sys; from pathlib import Path
n = int(sys.argv[2]) if len(sys.argv) > 2 else 80
text = Path(sys.argv[1]).read_bytes().decode("utf-8", errors="replace")
Path("tail.txt").write_text("\n".join(text.splitlines()[-n:]), encoding="utf-8")
```

## Правило 4: интерактивный REPL — только латиница

Путь с кириллицей, переданный в `python -i` через stdin, искажается —
`FileNotFoundError` на существующем файле. Многострочные вставки рвутся.
REPL — для латиницы и коротких однострочников, остальное — в файл.

## Правило 5: чисти за собой зависшие процессы

Долгий скрипт может пережить таймаут и остаться висеть, держа блокировки
и иногда выбрасывая модальное окно на экран пользователя. После таймаута:

```powershell
Get-Process python -ErrorAction SilentlyContinue | Select-Object Id,MainWindowTitle
Get-Process python -ErrorAction SilentlyContinue | Stop-Process -Force
```

Не перечисляй все процессы машины, чтобы найти один: это сотни строк.
Приложение по имени — `taskkill /F /IM MyApp.exe`.

## Правило 6: после записи — проверь, что файл изменился

Любой инструмент записи может отчитаться об успехе и не записать. Проверка
дешёвая: размер и время изменения файла или поиск характерной строки.

## Правило 7: перед пересборкой убей работающий exe

PyInstaller падает с `PermissionError: [WinError 5]` на `dist\app.exe`, если
приложение запущено, — видно только в конце лога. Первой строкой батника:

```bat
taskkill /F /IM MyApp.exe > nul 2>&1
```

Собирай один раз на пачку правок. Запустил — жди фиксированную паузу,
не опрашивай лог.

## Службы

Для служб — командлеты PowerShell (`Get-Service`, `Restart-Service`).
Перезапуск службы требует прав администратора.

## Быстрый чеклист

- Команда сложнее одной строки? → в файл
- Есть кириллица? → Python, не PowerShell
- Вывод битый? → проверить файл Python-ом, путь брать из листинга
- Лог от батника? → через `tail.py`
- Перезаписал файл? → проверь, что он реально изменился
- Ищешь процесс по имени? → `taskkill /IM`, не перечисление
- Пересобираешь? → сначала `taskkill`, один раз на пачку правок
- Вызов упал по таймауту? → проверь висящие процессы
