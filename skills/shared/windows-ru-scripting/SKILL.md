# Скриптование на русскоязычной Windows

На Windows проверь `$PSVersionTable.PSVersion`. `powershell.exe` запускает
Windows PowerShell 5.1, `pwsh.exe` — PowerShell 7. Команды `cmd.exe` и часть
старых программ могут выводить CP866. Работа через Desktop Commander в Claude
разобрана в `desktop-commander-bridge`.

## Правило 1: не передавай команды строкой, пиши файл

Инлайн-команда через `-Command "..."` проходит через несколько слоёв
экранирования: теряются `$переменные`, ломаются вложенные кавычки и обратные
кавычки, `python -c "..."` разваливается почти всегда.

Вместо этого: запиши скрипт в файл → запусти его одной строкой.

```
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File "...\job.ps1"
python -X utf8 "...\job.py"
cmd /c "...\job.bat"
```

Вложенные кавычки в `cmd /c "... & ..."` разваливаются так же, как в PowerShell.
Временные скрипты — вне папки проекта (`%TEMP%`).

## Правило 2: кодировка скрипта зависит от PowerShell

PowerShell 5.1 читает `.ps1` без BOM как ANSI. Для скрипта с кириллицей,
который должен работать в 5.1, используй UTF-8 с BOM. PowerShell 7 читает
UTF-8 без BOM. Сохраняй принятую в репозитории кодировку существующих файлов.

Если команда передаётся через инструмент, который искажает кириллицу или
кавычки, запиши скрипт в файл. Для обработки текста подходит `python -X utf8`.

## Правило 3: вывод консоли может прийти битым

Даже когда скрипт отработал верно, кириллица в выводе может прийти как
`2026 ????` или `╨Ъ╨╛╨╜`. Это косметика консоли, а не ошибка выполнения.
Помогает `PYTHONIOENCODING=utf-8` перед запуском Python.

- Проверять содержимое файла — Python-однострочником с `encoding="utf-8"`,
  а не `Get-Content` без `-Encoding UTF8`.
- Никогда не строй следующий путь из битого вывода: возьми настоящее имя
  листингом папки.

**Лог смешанной кодировки.** Если в один файл пишут и `cmd` (CP866), и Python
(UTF-8) — так получается у любого сборочного батника, — многие читалки файлов
откажутся его открыть как текст. Перекодируй хвост (заведи скрипт один раз
в начале работы, а не когда упрёшься):

```python
# tail.py <файл> [строк] -> tail.txt в чистом UTF-8
import sys; from pathlib import Path
n = int(sys.argv[2]) if len(sys.argv) > 2 else 80
text = Path(sys.argv[1]).read_bytes().decode("utf-8", errors="replace")
Path("tail.txt").write_text("\n".join(text.splitlines()[-n:]), encoding="utf-8")
```

## Правило 4: интерактивный REPL — только латиница

Путь с кириллицей, переданный в `python -i` через stdin, искажается —
`FileNotFoundError` на существующем файле. Многострочные вставки рвутся.
REPL — для латиницы и коротких однострочников, остальное — в файл.

## Правило 5: запускай долгие операции в фоне со сроком

Сеть, GUI и команды, которые могут зависнуть, запускай в фоне. Сохрани PID
запущенного процесса, направь вывод в лог и задай срок. По истечении срока
останови дерево именно этого процесса. Таймаут вызова инструмента сам по себе
может оставить дочерние процессы работать.

```powershell
$jobProcess = Start-Process -FilePath python.exe -ArgumentList '-X', 'utf8', '"C:\path with spaces\job.py"' `
    -WindowStyle Hidden -PassThru -RedirectStandardOutput $stdoutPath -RedirectStandardError $stderrPath
if (-not $jobProcess.WaitForExit(60000)) {
    taskkill /T /F /PID $jobProcess.Id
    exit 124
}
exit $jobProcess.ExitCode
```

В этом примере перед запуском задай пути `$stdoutPath` и `$stderrPath` к разным
файлам. Время ожидания подбери под задачу. Не останавливай все процессы
`python.exe` по имени.

## Правило 6: после записи — проверь, что файл изменился

Любой инструмент записи может отчитаться об успехе и не записать. Проверка
дешёвая: размер и время изменения файла или поиск характерной строки.

## Правило 7: перед пересборкой закрой запущенный экземпляр сборки

Запущенный экземпляр `dist\app.exe` блокирует перезапись файла в PyInstaller.
Перед сборкой проверь путь процесса и закрой именно этот экземпляр. Если он
не закрывается штатно, останови его по подтверждённому PID.

Собирай один раз на пачку правок. Дождись завершения сборки и проверь код
возврата и финальный файл.

## Правило 8: ловушки инструментов агента на этом ПК

- **Обратные слэши в heredoc.** Python-код через Bash heredoc (даже `<<'EOF'`) получает `\\` как `\`:
  `docs\2026` становится символом `\x82`, `agents\formats` — form feed, `split("\\n")` — настоящим
  переводом строки. Текст с Windows-путями править инструментами Edit/Write; скрипт-правку — файлом
  через Write, затем `python -X utf8 <файл>`. После массовой правки проверить файл на управляющие символы.
- **PowerShell 5.1 съедает внутренние двойные кавычки** в аргументах exe (`gh ... --jq '..."..."'`).
  Такие вызовы — из Bash: `"/c/Program Files/GitHub CLI/gh.exe" ...`. В своём терминале PowerShell путь
  к exe в кавычках — с `&` впереди.
- **Zip скилла для claude.ai** — только Python `zipfile` с путями `<имя>/SKILL.md`. `Compress-Archive`
  пишет обратные слэши, загрузка падает «path with invalid characters».
- **Установка в профиль.** В ограниченной сессии запись в профиль пользователя может быть
  недоступна. После установки проверь файл и запуск программы в пользовательском окружении.

## Службы

Для служб — командлеты PowerShell (`Get-Service`, `Restart-Service`).
Перезапуск службы требует прав администратора.

## Быстрый чеклист

- Команда сложнее одной строки? → в файл
- PowerShell 5.1 и кириллица в `.ps1`? → UTF-8 с BOM
- Вывод битый? → проверить файл Python-ом, путь брать из листинга
- Лог от батника? → через `tail.py`
- Перезаписал файл? → проверь, что он реально изменился
- Пересобираешь? → освободи выходной файл и проверь результат сборки
- Вызов упал по таймауту? → проверь дерево запущенного PID и лог
- Текст с `\`-путями? → Edit/Write, не heredoc
