# Автоматизация GUI-приложения без API

Задача: заставить десктопную программу что-то делать по расписанию или по
событию, когда у неё нет ни скриптования, ни командной строки.

## Порядок действий — строго такой

### 1. Сначала ищи путь БЕЗ интерфейса

Прежде чем автоматизировать клики, проверь:

- есть ли у программы CLI или скриптовый API на этой платформе
- хранит ли она настройки в текстовых файлах, которые можно писать напрямую
- есть ли механизм «применить при импорте»

**Но проверяй экспериментом, а не рассуждением.** Заманчивая идея «подсуну
файл настроек мимо программы» может провалиться: закрытые форматы содержат
обязательные поля, которых нет в том, что ты копируешь, и программа отвергнет
файл целиком. Один тестовый файл стоит часа теории.

Если обход не вышел — не реверси закрытый формат ради процесса, который должен
работать без присмотра. Иди в интерфейс.

### 2. Сними параметры окна

```python
from pywinauto import Application
app = Application(backend="uia").connect(path="App.exe", timeout=20)
win = app.top_window()
print(win.window_text(), win.element_info.class_name)
```

Класс окна говорит о технологии: `WindowsForms10.*` — WinForms,
`HwndWrapper[...]` — WPF, `Qt*` — Qt. **У одной программы главное окно и
диалоги могут быть на разных технологиях** — это нормально и важно.

### 3. Проверь файл горячих клавиш

Многие программы держат раскладку шорткатов в XML в `AppData`. Оттуда сразу
видно, какие команды вообще существуют — и есть ли нужная.

Коды обычно `модификаторы * 0x10000 + виртуальный код клавиши`, где
Shift=1, Ctrl=2, Alt=4. `131137` = `0x20041` = Ctrl+A.

Это даёт два ответа сразу: какие клавиши можно слать напрямую и чего в
принципе нельзя назначить (набор команд фиксирован приложением — динамические
сущности вроде пользовательских пресетов там не появятся).

### 4. Ходи по меню ПО НАЗВАНИЯМ, не по координатам

Координаты ломаются при переносе окна и смене разрешения. Навигация стрелками
ломается при пересортировке списка. Названия — нет.

```python
def unwrap(children):
    # WinForms прячет пункты внутри обёртки Menu — иногда в несколько слоёв
    for _ in range(3):
        if len(children) == 1 and children[0].element_info.control_type == "Menu":
            children = children[0].children()
        else:
            break
    return children

def expand(item):
    try:
        item.expand()
    except Exception:
        item.click_input()
    time.sleep(0.55)
    return unwrap(item.children())
```

Без `unwrap` первый же `children()` вернёт один элемент типа `Menu` вместо
списка пунктов, и покажется, что подменю пустое.

Поиск пункта: сначала точное совпадение текста, потом вхождение подстроки,
регистр игнорировать.

### 5. Диалоги — отдельные окна, обходить их дерево опасно

Модальный диалог часто оказывается самостоятельным top-level окном другого
класса. Рекурсивный обход его дерева может **повесить скрипт на минуты** и
оставить диалог висеть на экране пользователя.

Перед обходом ограничивай глубину. Всегда закрывай диалог в `finally` через
`{ESC}`. Если обход завис — прибери процесс и закрой окно отдельным лёгким
скриптом.

**Разовые действия не автоматизируй.** Создание проекта, первичная настройка,
мастер установки — это тридцать секунд ручной работы против часа отладки
диалогов. Отдай их пользователю и скажи об этом прямо.

### 6. Что осталось — шли клавишами

Если команда есть в файле шорткатов, но её нет в меню — шли клавишу:

```python
win.set_focus()
time.sleep(0.4)
send_keys("^d")
```

Слать клавиши безопасно сразу после вызова пункта меню — фокус возвращается
в главное окно, а не в текстовое поле.

## AutoHotkey как второй инструмент

AHK ставится через `winget install --id AutoHotkey.AutoHotkey -e --silent`,
ложится в `C:\Program Files (x86)\AutoHotkey\v2\AutoHotkey64.exe`.

Он полезен там, где UIA тяжёл: быстро перечислить окна процесса, послать
клавишу, закрыть зависший диалог.

**Грабля v2:** `FileDelete` на отсутствующем файле выбрасывает исключение и
показывает пользователю модальное окно с ошибкой. Оборачивай в `try`. То же
для любой файловой операции в AHK.

## Проверка результата — обязательна

UI-автоматизация ненадёжна по своей природе: окно свернули, фокус увели,
программа задумалась. Никогда не считай, что действие выполнилось, потому что
вызов не упал.

Проверяй по наблюдаемому следствию — появился файл, изменился размер, выросла
папка. И закладывай повтор: операция должна быть идемпотентной, чтобы второй
заход не навредил.
