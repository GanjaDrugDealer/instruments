# План переноса: Google Диск → C:\AI Projects

Дата: 2026-09-15. Документ рассчитан на исполнение любым агентом
(Claude, Antigravity) на машине ganjahome, Windows 11, русская локаль.

## Зачем

Google Диск (том K:) — не NTFS. Из этого следовали три ограничения:
symlink и junction на самом Диске невозможны; `.venv` и `node_modules`
пересинхронизируются целиком; исключений по маске у Диска нет.
Локальный NTFS снимает все три.

Замер до переноса: 686 МБ, 12 894 файла. Из них два `.venv` — 338 МБ
и 94% файлов. На C: свободно 109 ГБ.

## Целевая структура

```
C:\AI Projects\
├── _Instruments\                общее для всех агентов
│   ├── skills\
│   │   ├── shared\              скиллы, работающие у обоих агентов
│   │   ├── claude\              только Claude Code / Cowork
│   │   └── antigravity\         только Antigravity
│   ├── agents\                  роли и промпты
│   ├── docs\                    сквозные знания
│   ├── templates\project\       шаблон нового проекта
│   └── _archive\                отключённое старое
├── Claude\<project-name>\
└── Antigravity\<project-name>\
```

Структура проекта — одинаковая в обеих ветках:

```
<project-name>\
├── CLAUDE.md          единственный содержательный файл контекста
├── AGENTS.md          стаб: ведёт в CLAUDE.md, называет папку скиллов
├── GUARDRAILS.md      ограничения, п.1 — работать только внутри папки
├── .env.example       имена переменных окружения, без значений
├── .claude\skills\    скиллы проекта: <имя>\SKILL.md
├── docs\ agents\ mcp\ scripts\ src\ data\ out\
└── .venv\ .git\ node_modules\   на локальном диске разрешены
```

## Скиллы: факт, установленный проверкой

Формат скиллов у Claude и Antigravity **идентичен**: папка `<имя>\SKILL.md`,
вложенность ровно один уровень, фронтматтер с `name` и `description`.
Один и тот же файл читается обоими — проверено на файле
`project-structure\SKILL.md`, подключённом junction'ом одновременно в
`.claude\skills` и `.gemini\config\skills`.

Папка с двумя уровнями вложенности не загружается ни у одного из них.
Это была причина, по которой прежняя схема сбора скиллов не работала.

Не переносится только содержимое, привязанное к инструментам конкретного
агента. Поэтому деление — по содержимому, а не по агенту:

| Папка | Что кладём | Куда линкуется |
|---|---|---|
| `skills\shared\` | знания: железо, пути, конвенции, правила ОС, доменные процессы через команды ОС | в оба агента |
| `skills\claude\` | Desktop Commander, device_bash, специфика Cowork | `.claude\skills` |
| `skills\antigravity\` | тулзы и слэш-команды Antigravity | `.gemini\config\skills` |

Раздача — одна команда на скилл, один раз:

```cmd
mklink /J "C:\Users\Артем Ганжа\.claude\skills\<имя>"        "C:\AI Projects\_Instruments\skills\shared\<имя>"
mklink /J "C:\Users\Артем Ганжа\.gemini\config\skills\<имя>" "C:\AI Projects\_Instruments\skills\shared\<имя>"
```

Скиллы Cowork — аккаунтные, файлом с диска не подключаются. Папка для него
мастер-копия, а не источник загрузки.

## Порядок переноса

Шаги 1-8 выполняются один раз. Ничего не удаляется до шага 8.

1. **Снять действующие junction'ы** в профиле пользователя:
   `rmdir "C:\Users\Артем Ганжа\.claude\skills\project-structure"` и то же
   для `.gemini\config\skills`. `rmdir` на junction убирает ссылку, цель цела.

2. **Остановить процессы**, держащие файлы: закрыть Antigravity, Claude Desktop,
   редакторы. `taskkill /F /IM <exe>` при необходимости.

3. **Скопировать** дерево целиком, без удаления источника:
   `robocopy "K:\Мой диск\AI Projects" "C:\AI Projects" /E /R:2 /W:2`
   Копирование, не перемещение: Диск остаётся нетронутым до проверки.

4. **Переименовать** `Instruments` → `_Instruments`, разложить скиллы
   по трём папкам `shared\ claude\ antigravity\`. Сейчас общий скилл
   ровно один — `project-structure` → в `shared\`.

5. **Удалить пустышку** `Antigravity\Instruments\` (указатель «переехало»,
   после переноса не нужен) и все `desktop.ini` — это артефакты Google Диска.

6. **Пересоздать junction'ы** на новые пути (см. раздел выше).

7. **Проверить**: у каждого проекта на месте `CLAUDE.md`, `AGENTS.md`,
   `GUARDRAILS.md`, `.env.example`, `.claude\skills\`; junction'ы читаются
   насквозь; счётчик файлов совпал с исходным (12 894).

8. **Только после проверки** — убрать исходную папку с Диска. Рекомендуется
   не удалять, а переименовать в `AI Projects _OLD` и удалить через неделю.

## Что меняется в правилах после переноса

Снимается запрет на `.git`, `.venv`, `node_modules` внутри папки проекта:
на локальном NTFS они безвредны. Остальные правила в силе:

- Папка проекта самодостаточна: открыл в любом агенте — работает.
- Абсолютных путей наружу в файлах проекта нет.
- Реальных секретов в проекте нет, только `.env.example`.
- Один файл контекста — `CLAUDE.md`; `AGENTS.md` и `.antigravity\GEMINI.md`
  стабы со ссылкой на него.
- Имена: латиница, kebab-case, без пробелов. Документы:
  `ГГГГ-ММ-ДД_название-латиницей.md`.
- Библиотека — источник, проекты — потребители. Сбор скиллов из проектов
  в библиотеку запрещён.

## Новый проект — одинаково в любой агентной системе

```cmd
new-project.bat <Claude|Antigravity> <project-name>
```

Батник копирует `_Instruments\templates\project\` в нужную ветку.
Дальше: заполнить `CLAUDE.md`, удалить ненужные папки шаблона, при
необходимости положить скиллы проекта в `.claude\skills\`.

Подключение готовой папки:

- Claude Code / новый аккаунт Claude: открыть папку как рабочую директорию.
  `CLAUDE.md` и `.claude\skills\` подхватятся сами.
- Antigravity: открыть папку как workspace, точка входа — `AGENTS.md`.
- Локальный агент (Ollama и подобные): `CLAUDE.md` как системный контекст,
  `.claude\skills\*\SKILL.md` как дополнительные инструкции.

## Бэкап и переносимость на ноутбук

Локальный диск бэкапа не даёт. Взамен синхронизации всей папки — ночное
зеркало с исключениями, которое Google Диск делать не умеет:

```cmd
robocopy "C:\AI Projects" "<облачная папка>\AI Projects" /MIR ^
  /XD .venv node_modules __pycache__ build dist .antigravity
```

Переносит осмысленные ~350 МБ, пропускает 338 МБ пересоздаваемого.
Ставится в Планировщик задач на ночь.

Для проектов с кодом правильный инструмент — git с удалённым репозиторием,
а не файловая синхронизация.

**Открытый вопрос:** конечная облачная папка не выбрана. Кандидаты на машине:
Яндекс.Диск, Nextcloud, OneDrive, Google Диск. Решение за пользователем.
